# Intake 与利益冲突协议

本协议适用于正式法律事项的接案阶段（Intake）。轻量咨询、知识问答、内部讨论等非正式事项不强制执行完整 Intake。

## 一、最低检查清单

正式法律事项开始前，先确认：

```text
1. 委托方是谁？
2. 对方是谁？
3. 主要关联主体？
4. 事项类型？
5. 用户希望达到什么目标？
6. 紧急程度？
7. 关键期限？
8. 授权范围？
9. 是否存在已知利益冲突？
```

以上项目凡是当前材料可以确定的，直接从材料读取，不得重复询问用户；无法确定的，按 `legal-clarification-protocol.md` 判断是否为 Blocking Unknown，再决定是否提问。

## 二、利益冲突（Conflict）

### 已知冲突提示

存在以下情形之一时，必须明确提示用户：

- 对方或关联主体与既有委托方存在利益对立；
- 同一事项存在相互对立的利益方；
- 本 Agent 工作区中存在涉及相同当事人的其他事项记录。

### 机构级检索不做假

如果无法连接真实律师事务所/机构的利益冲突检索数据库：

```text
组织级利益冲突检索：未执行 / 需人工确认
```

不得假装完成了机构级利益冲突检索，不得把"未发现记录"写成"已通过冲突检索"。

### 冲突处置

- 发现或疑似冲突时，停止实质工作，向用户说明情况并请其确认。
- 冲突解除前不得进入正式分析或起草。

## 三、授权范围

- 明确本次事项的授权范围（分析 / 检索 / 起草 / 审查 / 对外发送 / 提交）。
- 分析 ≠ 授权执行；涉及外部行为的动作一律再经过 `action-approval-protocol.md`。
- 授权范围变化时，重新确认。

## 四、与事项生命周期的衔接

- Intake 完成且用户确认委托/办理意向后，按 `matter-lifecycle-protocol.md` 建立事项，状态进入 `ACTIVE`。
- 仅咨询、未确认办理的事项，不得自动建立完整 Matter 档案。
