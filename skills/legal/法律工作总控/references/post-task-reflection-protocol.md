# 任务后反思协议（Hermes-style Post-task Reflection）

## 核心约束

**本协议绝不授权 Agent 自动修改 Skill。**

禁止 Agent 自动：

```text
- 改写 SKILL.md
- 改写 protocol
- 安装新 Skill
- 修改权重
- 修改系统规则
```

Self-evolution 在本项目中的唯一含义：

```text
Task completed → Reflection → Reusable lesson
```

即：任务结束后，把可泛化的失败经验沉淀为一条去敏化的经验规则，写入 `knowledge/lessons.md`。仅此而已。

## 只有以下情况才记录

- Agent 实际犯错并被用户/材料纠正；
- 走过明显错误路径（例如把当事人主张直接当作已核实事实）；
- 发现稳定可复用的边界条件（例如某类材料格式存在稳定陷阱）；
- 用户纠正了可泛化的专业工作方法；
- Ludus 反向复核发现一个过去容易忽略的失败机制；
- 某工具/材料格式存在稳定陷阱。

## 不记录

```text
- 普通任务摘要
- 客户姓名、身份信息、联系方式
- 案号
- 个案金额
- 私密事实
- 临时路径
- 一次性结论
- 普通法律知识
```

## 归档流程

```text
发现经验
↓
是否真正可复用？（个案特有 → 不记录）
↓
去个案化
↓
去敏感信息
↓
抽象规则
↓
检查 lessons.md 是否已有同义规则
↓
新增 / 合并经验
```

## 记录格式

```md
### [标题]

**触发条件**
...

**失败点**
...

**修正**
...

**以后应当**
...
```

不写长篇 Task Diary。任务正常成功时，不写 lessons。

## 写入位置

- 通用经验写入仓库 `knowledge/lessons.md`。
- 写入前必须检查是否与既有条目同义，同义则合并。
- 不得写入客户材料、案卷、系统记录区以外的任何个案信息。
