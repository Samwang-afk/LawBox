# 推理等级协议

本协议决定一个法律任务需要多深的推理，与 `routing-map.md` 分工不同：routing-map 决定"调用哪个业务 Skill"，本协议决定"推理走多深"。所有任务先路由，再按本协议分类推理等级。

可执行参照实现：`skills/legal/法律工作总控/scripts/reasoning_control.py classify`。该脚本只实现确定性决策规则；Agent 负责填写任务属性。

## 一、四个等级

### L0 — Direct

适用：单一明确法律知识问题；几乎不依赖案件事实；无竞争性解释；无重大策略；不生成高风险正式法律成果。

流程：必要事实确认 → 必要法律来源核验 → 直接回答。

- 不建立 Matter Model。
- 不运行 Advocate / Challenger / Judgment。
- 法规核验仍然适用 `pkulaw-mcp-legal-verification-protocol.md` 和 `source-boundary-protocol.md`。

### L1 — Standard

适用：普通合同分析、简单案件分析、事实结构较明确、简单文书、普通法律适用，且不存在显著竞争性法律路径。

流程：读取 → 简化 Matter Model → 必要澄清 → 专业 Skill → 输出。

- 建立简化 Matter Model（可只在工作上下文维护）。
- 澄清遵循 `legal-clarification-protocol.md`。
- 不强制 Advocate / Challenger / Judgment。
- 正式文书仍必须走既有 `法律文书出稿前审查` 与导出链路。

### L2 — Deliberative

满足以下任一条件时原则上进入 L2：

- 存在两个以上合理法律关系；
- 存在两个以上合理请求权基础；
- 关键事实存在争议；
- 证据存在竞争性解释；
- 需要选择诉请；
- 需要选择抗辩；
- 需要判断程序策略；
- 用户要求胜诉分析、责任判断、诉讼策略、法律风险比较；
- 结论高度依赖未知事实。

流程：完整 Matter Model → Clarification → 专业法律分析 → 更新 Matter Model → Advocate → Challenger → Judgment →（起草许可）→ 起草。

### L3 — Adversarial

适用：重大诉讼；正式法律意见；高影响合同；重大交易风险；关键刑事辩护策略；不可逆程序决定；用户明确要求反方压力测试；初步判断存在高度不确定；一个错误结论可能造成严重后果。

L3 除 L2 全部要求外，必须：

- 主动检索反向法规；
- 主动检索不利案例；
- 主动寻找相反裁判思路；
- 构建最强对方论证；
- 识别结论失败的最小条件集合；
- 明确 residual uncertainty。

## 二、分类规则

禁止按任务长度分类。只考察三项：决策复杂度、不确定性、后果。

选择满足任务需要的最低充分推理等级。

```text
属性填写（由 Agent 在分类时判定）：
- task_type: knowledge_question | case_task | contract_task | document_task
- 任意 L3 触发项为真 → L3
- 否则任意 L2 触发项为真 → L2
- 否则 knowledge_question → L0
- 否则（有事项上下文的任务）→ L1
```

L3 触发项：重大诉讼、正式法律意见、高影响合同、重大交易风险、关键刑事辩护策略、不可逆程序决定、用户要求反方压力测试、高度不确定、错误结论可能造成严重后果。

L2 触发项：两个以上合理法律关系、两个以上合理请求权基础、关键事实争议、证据竞争性解释、需选择诉请、需选择抗辩、需程序策略判断、胜诉分析/责任判断/诉讼策略/风险比较请求、结论高度依赖未知事实。

## 三、动态升级

- 允许 L0 → L1、L1 → L2、L2 → L3 升级；新事实出现后重新分类。
- 新事实使复杂度下降时，一般无需降级重跑已完成的高等级分析，但后续可停止不必要步骤。
- 简单咨询不得因本协议变得厚重：L0 保持轻量。

## 四、等级与持久化

- L0：不持久化 Matter Model。
- L1：仅在内部工作上下文维护简化 Matter Model；要点可写入系统记录区 `工作笔记.md`。
- L2：在系统记录区 `推理记录/matter-model.md` 形成结构化 Matter Model。
- L3：系统记录区 `推理记录/` 下形成 `matter-model.md`、`review.md`、`judgment.md` 三件套。

`推理记录/` 属于内部分析层，不进入业务文件区，不得交付客户。

## 五、与其他层的关系

- 推理等级只控制认知深度；业务 Skill 选择仍由 `routing-map.md` 负责。
- 专业法律分析（`初步法律分析` 的六来源体系、请求权基础、要件审判）在所有等级中都是领域推理核心；L2/L3 在其上增加对抗审议与裁决。
- 交付质量门（`法律文书出稿前审查`、`法律文书模板与导出`）在所有等级保持强制，不受推理等级豁免。
